# Implementation milestones

The original specification is preserved in `BUILD_PLAN.md`.

**[v0.1.5 is published and deployed](https://github.com/Addison16/commanders-table/releases/tag/v0.1.5)** following the user's explicit request. It adds **View commander** in player profiles, with full card images, readable rules text, partner selection and double-faced cards. Approved guests can read any player's commander while editing permissions stay unchanged. Home settings are easier to find, and life-control feedback is circular while preserving the existing touch areas. Card-route rate limits now return 429 instead of an accidental 500. There is no game-save or SQLite schema change.

[Main verification](https://github.com/Addison16/commanders-table/actions/runs/35279446793) passed. Every validation job in the [release workflow](https://github.com/Addison16/commanders-table/actions/runs/35279446951) also passed: 137 unit/integration checks, 71 Chromium/WebKit browser cases with 3 expected skips, production offline/update and HTTPS/WSS checks, and native amd64/arm64 container smoke tests. The images and release were published; GitHub returned HTTP 500 while uploading `compose.yaml`, and retrying only that missing attachment completed the downloads. The workflow retains that upload failure in its status. Anonymous checks verified both release assets, both 130-file source archives, both image platforms and embedded license files, an actual Docker pull, unchanged earlier release digests and the package page's `latest` command. The public image passed a separate x64 container smoke test and is deployed with the same configuration and volume. A verified backup and the previous image were retained, and all saved records matched exactly after the update. Container and HTTPS health checks passed. A live browser retained its exact game across the release reload, then read real Jace front/back scans, rules and loyalty without changing that game; [testing evidence](testing.md) records the completed checks. The records below describe earlier milestones and deployments at the time they were completed.

**[v0.1.4 was published and deployed](https://github.com/Addison16/commanders-table/releases/tag/v0.1.4)**, combining optional commander artwork, one-step player saves, automatic player dice colors and the browser storage-abort fix. [Main verification](https://github.com/Addison16/commanders-table/actions/runs/35213830032) and the [release workflow](https://github.com/Addison16/commanders-table/actions/runs/35213830381) passed 128 unit/integration checks, 63 Chromium/WebKit browser cases with 3 expected skips, production offline/update and HTTPS/WSS checks, and native amd64/arm64 container smoke tests. Public release downloads, source archives, both image platforms and license metadata were verified anonymously, including an actual Docker pull and isolated container smoke test. The package page displayed the `latest` pull command, and earlier release digests were unchanged. The service was updated to the public v0.1.4 image with all saved records preserved; a live browser retained its game and verified the unified save and matching dice color.

Joining-player setup: shared guests choose their own player name and optional one or two commander labels before requesting a seat. The host sees the choices and applies them with the existing approval action. Requests persist across refresh/restart and can be revised while pending. Approval preserves game totals and existing identities, supports partners, and retains own-seat editing during play. SQLite migration 2 adds only the nullable pending-profile column.

September 16 follow-up requests are implemented: shaded 3D dice bounce over the life-counter board, including every player's d20 and tie rerolls; the first player is revealed after rolling. Names and commanders can be edited at the top of player details. Extra trackers were removed from Utilities. Turn tracking is opt-in with Next turn beside Undo. New game asks one phone or multiple phones, and Home resumes the last ten unfinished local/shared games. Dice also work on ended games, all approved guests can roll for everyone, and expired local editor leases recover automatically. These user-requested changes supersede the original utility presentation requirements.

The later presentation requests are implemented too: dice have cleaner beveled edges, softer shading and centered, upright result faces. **Game menu → Table layout → Shared table** provides four large counters on a sideways phone, facing two players on each side. Layout choice is remembered on that phone, with individual seat flips still available.

The next refinement replaces painted dice bevels with genuinely rounded geometry and an ivory material. Ending a game returns to the starting options; local games and shared rooms can be reopened with their original state for 24 hours. Dice audio now uses a clearer clatter, handles suspended audio contexts and offers an explicit preview in settings.

[v0.1.1](https://github.com/Addison16/commanders-table/releases/tag/v0.1.1) changes the application and original assets to [MIT with Commons Clause](https://github.com/Addison16/commanders-table/blob/v0.1.1/LICENSE), with no gameplay or storage changes. This is source-available licensing; v0.1.0 and its existing MIT permissions remain unchanged. The [release workflow](https://github.com/Addison16/commanders-table/actions/runs/35165571310) passed the full verification gate. Public `0.1.1`, `latest` and `stable` images, both platforms' license labels and embedded license files, and release downloads were verified anonymously. The [v0.1.2 update](https://github.com/Addison16/commanders-table/releases/tag/v0.1.2) adds player-colored pearl dice, uses the homepage symbol consistently for the header/favicon/install icons, and fixes confirmed live-form, reconnect, concurrent-storage, editor-tab and recovery issues. Its [PolyForm Noncommercial license](../LICENSE) prohibits commercial use while preserving earlier release permissions and third-party terms. The [release workflow](https://github.com/Addison16/commanders-table/actions/runs/35168229381) passed 84 unit/integration checks, 49 browser cases with 3 expected skips, offline/update and HTTPS checks, and native amd64/arm64 container checks. Public images, license metadata and release downloads were verified anonymously. The deployment was updated to the published v0.1.2 image with all saved records preserved; a live browser update retained its exact game and verified the new colored dice and unified icons. The source checkout was synchronized with GitHub after that release.

The v0.1.3 commander-artwork update adds Scryfall name suggestions and card-link lookup to setup, joining and in-game edits. Optional artwork follows partners, seat approval, saved games and rematches, with artist attribution and a bounded offline image cache. Manual names and counters remain usable when searches or images fail. Local verification passes 110 unit/integration checks and 57 browser cases with 3 expected skips, plus production offline/update, real-art cache and HTTPS checks. The source was pushed before publication was stopped; the release workflow was canceled before creating a GitHub release or Docker image. At that point, public releases remained at v0.1.2. The verified `0.1.3-local` image was deployed locally with saved records preserved, and the live browser update, real card lookup, cached artwork and colored dice passed. The local-only publication preference remains in effect except when the user explicitly requests a release, as they have for v0.1.4.

The subsequent player-editing update combines player name, color and commander labels/artwork into one **Save changes** action with one undo entry. Drafts clear only after a durable local save or the room’s successful acknowledgement; failed saves retain all edits. A local roll now defaults to the most recently saved or selected player and reads their current color. Shared guests still default to their own seat, and **The table** remains an explicit ivory option. A browser storage-abort regression was also fixed. These changes were first verified and deployed locally on September 16; they are now included in the published v0.1.4 source and images, and the existing service has been updated to that public image.
