# Implementation milestones

The original specification is preserved in `BUILD_PLAN.md`.

Joining-player setup: shared guests choose their own player name and optional one or two commander labels before requesting a seat. The host sees the choices and applies them with the existing approval action. Requests persist across refresh/restart and can be revised while pending. Approval preserves game totals and existing identities, supports partners, and retains own-seat editing during play. SQLite migration 2 adds only the nullable pending-profile column.

September 16 follow-up requests are implemented: shaded 3D dice bounce over the life-counter board, including every player's d20 and tie rerolls; the first player is revealed after rolling. Names and commanders can be edited at the top of player details. Extra trackers were removed from Utilities. Turn tracking is opt-in with Next turn beside Undo. New game asks one phone or multiple phones, and Home resumes the last ten unfinished local/shared games. Dice also work on ended games, all approved guests can roll for everyone, and expired local editor leases recover automatically. These user-requested changes supersede the original utility presentation requirements.

The later presentation requests are implemented too: dice have cleaner beveled edges, softer shading and centered, upright result faces. **Game menu → Table layout → Shared table** provides four large counters on a sideways phone, facing two players on each side. Layout choice is remembered on that phone, with individual seat flips still available.

The next refinement replaces painted dice bevels with genuinely rounded geometry and an ivory material. Ending a game returns to the starting options; local games and shared rooms can be reopened with their original state for 24 hours. Dice audio now uses a clearer clatter, handles suspended audio contexts and offers an explicit preview in settings.
